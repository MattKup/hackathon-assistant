# Помощник по регламентам проектной деятельности

> Черновик README (26.11, ночь). Финальная версия — после выбора версии для стенда. Цифры — только в формулировке ADVANTAGES §Ж.

Хакатон «ИИКузница» 26–28.11.2026, задача «Поиск ответов по корпоративным документам». Сотрудник спрашивает в чате — помощник отвечает **строго по тексту регламентов** с пунктами и дословными цитатами; если вопрос допускает разные ответы — уточняет; если ответа в регламентах нет — не додумывает, а передаёт вопрос в службу качества, а ответ эксперта становится знанием помощника. Всё работает локально, на открытых моделях.

## Три кейса задачи

| Кейс | Как это сделано |
|---|---|
| 1. Ответ строго по регламенту; нет ответа — запрос в службу качества | Ответ по каждой дирекции с пунктом и дословной выдержкой; цитаты, числа, роли и «можно/нельзя» сверяются с текстом пункта **кодом**; без опоры — письмо в службу качества (сотрудник в копии), сотрудник видит «Вопрос передан, обращение №…». В письме — вопрос, диалог, близкие пункты и черновик для эксперта (второй проход модели) |
| 2. Уточняющий диалог | Ответы дирекций различаются, а дирекция не названа → вопрос с кнопками дирекций («Проект нескольких дирекций», «Не знаю» — ответ по всем); ответ зависит от условия из пункта → один вопрос словами пункта; размытый вопрос → близкие темы из регламентов |
| 3. Дообучение через службу качества | Эксперт отвечает на письмо → промежуточный ответ не публикуется, итоговый становится карточкой знания → эксперт подтверждает → повторный вопрос другими словами отвечается по карточке без нового письма; регламент главнее: карточка службы качества дополняет пункты, а если расходится с действующим пунктом — сотрудник получает правило регламента и предупреждение, служба качества — письмо «изменить регламент или отозвать карточку» |

Опция (выключена по умолчанию, переключатель в чате «подсказки «проверьте также»»): если рядом с процитированным пунктом есть пункт с исключением или особым условием по той же теме, помощник показывает его дословно — «Ответ может быть неполным — проверьте также п. X». Подсказку строит код, без модели. На 4 регламентах чаще показывает лишние пункты, чем нужные; рассчитана на большую базу и другие модели.

Дополнительно: **противоречия в регламентах** (ночной анализатор находит кандидатов → служба качества подтверждает на странице «Противоречия» → помощник показывает оба пункта и пишет в СК); **мониторинг повторов** («этот вопрос задавали N раз за период» → сигнал службе качества и в аналитику); **загрузка документов** (DOCX, PDF и сканы через doc-intel, страницы Confluence) — новое подразделение без правки кода.

## Как устроено

```
вопрос ─► разбор (LLM: термины регламента, дирекции, тип вопроса)
        ─► поиск: BM25 + bge-m3 → RRF → реранкер bge-reranker-v2-m3 (сначала по всей базе, затем вглубь в лучших документах)
        ─► ответ по каждой дирекции параллельно (LLM, JSON-схема, дословные цитаты)
        ─► агентный проход для слабых ответов (добор пунктов по ссылкам «п. X.Y», соседних и недостающих → второй ответ)
        ─► проверки кодом (цитата, числа, роли, запрет↔разрешение, опора каждой фразы краткого ответа)
        ─► решение: ответ / уточнение / письмо в СК / «вне регламентов» (+ реестр подтверждённых противоречий, практика СК)
```

- **Нормализатор документов** (`app/chunking`, `app/parsers`, `app/ingest`): нарезка по пунктам / по заголовкам / без раздела, окна 600–1000 знаков с путём раздела; DOCX, HTML/Confluence, PDF и сканы (doc-intel, разделы `sectionPath`).
- **Конфигурация вместо кода** (`config/documents.json`): подразделения, синонимы, роли, маршруты «вне регламентов», мониторинг повторов, пространства Confluence.
- **Коннектор Confluence** (`app/connectors/confluence.py`): Cloud v2 и Server/DC, без аддонов, инкрементально по версии страницы (проверен на записанных ответах API).
- **Служба качества** (`app/escalation`): обращения, письма (SMTP; в демо — Mailpit), разбор ответов эксперта, карточки знаний, черновик для эксперта, сигнал повторов.
- **Противоречия** (`app/analysis/conflicts.py`, `app/analysis/registry.py`): ночной анализатор (кандидаты по теме и общему действию, сигналы кодом, судья LLM, проверка цитат) → реестр с подтверждением службой качества.

## Модели и лицензии (всё локально, внешних API нет)

| Роль | Модель | Лицензия |
|---|---|---|
| Ответы, разбор вопроса, черновик для СК | [Qwen3.8-27B AWQ INT4](https://huggingface.co/cyankiwi/Qwen3.8-27B-AWQ-INT4) (база [Qwen/Qwen3.8-27B](https://huggingface.co/Qwen/Qwen3.8-27B)), vLLM | Apache-2.0 |
| Эмбеддинги | [BAAI/bge-m3](https://huggingface.co/BAAI/bge-m3), TEI | MIT |
| Реранкер | [BAAI/bge-reranker-v2-m3](https://huggingface.co/BAAI/bge-reranker-v2-m3), TEI | Apache-2.0 |
| Распознавание сканов (опция) | [LightOnOCR-2-1B](https://huggingface.co/lightonai/LightOnOCR-2-1B) через doc-intel | Apache-2.0 |

Конфигурация стенда — одна RTX 5090 32 ГБ. Для сканов и PDF — опционально второй узел RTX 3090 с LightOnOCR.

## Запуск

```bash
# демо без стенда (BM25 + заглушка модели) — интерфейс и сценарии
python3 -m app.api.server --corpus <папка с регламентами> --data data/app --mock --port 8080
# стенд: docker compose (TEI, vLLM, doc-intel — адреса в deploy/compose.yaml)
cd deploy && docker compose up -d
```
Роли в интерфейсе: «Сотрудник» (чат) и «Служба качества» (обращения, знания, противоречия, аналитика, загрузка документов).

## Проверка качества

`scripts/eval/answer_eval.py` — прогон эталона вопросов; `scripts/eval/funnel.py` — воронка (поиск → контекст → цитата в ответе → исход → оценка судьи) и парное сравнение прогонов; судья по существу — рубрика `review/judge/RUBRIC.md` в репозитории проекта. Тесты: `python3 -m unittest discover -s tests`.

## Анализатор противоречий — запуск

**Анализатор противоречий** (`app/analysis/conflicts.py`): офлайн-поиск противоречий, неоднозначностей, зависимостей и различий дирекций между пунктами регламентов — кандидаты по теме и сигналам кода, судья LLM, цитаты проверяются кодом. Задача раннера `conflicts`: `scripts/stand/conflicts.sh <корпус>`.

- **Ночной режим** (по умолчанию): точность выше стоимости — все пары после фильтра, мягкий судья (полнота), затем каждая находка перепроверяется тремя независимыми судьями (ревизор A→B, ревизор B→A, «адвокат регламента»); итог по большинству с полем «уверенность», отклонённое — отдельным разделом отчёта. Быстрый режим: `<корпус> 300` (бюджет пар, без перепроверки). Без стенда: `--offline`.
- **Инкрементально**: `<корпус> prev=<metrics.json прошлого прогона>` — только пары, где есть пункт нового/изменённого документа (doc_id = sha256 файла); или `changed=<префикс doc_id>,…`.
- **По расписанию** (в часы наименьшей нагрузки; на стенде ничего не ставится автоматически): строка crontab на машине раннера, напр. каждую ночь в 02:00 — `0 2 * * * cd ~/hackathon-runs && python3 tools/submit.py conflicts --ref <коммит> --timeout 240 -- <корпус>`; раз в неделю — `0 2 * * 0 …`; после загрузки новых версий документов — тот же вызов с `prev=…` (только их пары). Отчёт `conflicts.md` — для службы качества.
- Кандидаты сразу в реестр сервера: `scripts/eval/conflicts.py <корпус> db=<data/app.sqlite>`; или `POST /api/conflicts/import` с conflicts.json.
