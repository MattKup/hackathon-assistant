# Помощник по регламентам проектной деятельности

Хакатон «ИИКузница» 26–28.11.2026, задача «Поиск ответов по корпоративным документам» (4 регламента: Техническая дирекция, Дирекция ИБ — пресейл и проект, ДБРЦТ).

Сотрудник спрашивает в чате своими словами. Помощник отвечает **строго по тексту регламентов**: по шагам, с пунктом и дословной цитатой. Если вопрос допускает разные ответы — уточняет. Если ответа в регламентах нет — не додумывает, а передаёт вопрос в службу качества (СК); ответ эксперта становится знанием помощника. Всё работает локально, на открытых моделях, на одной видеокарте.

## Три кейса задачи

| Кейс | Как сделано |
|---|---|
| **1. Строго по регламенту; нет ответа — в службу качества** | Ответ по каждой дирекции с пунктом и дословной выдержкой. Цитаты, числа, роли и «можно / нельзя» сверяются с текстом пункта **кодом**. Нет опоры — письмо в СК (сотрудник в копии) с вопросом, диалогом, близкими пунктами и черновиком ответа для эксперта; сотрудник видит «Вопрос передан, обращение №…». |
| **2. Уточняющий диалог** | Ответы дирекций различаются, а дирекция не названа → вопрос с кнопками дирекций («Не знаю» — ответ по всем). Ответ зависит от условия из пункта → один вопрос словами пункта. Размытый вопрос → близкие темы из регламентов. |
| **3. Дообучение через службу качества** | Эксперт отвечает на письмо → промежуточный ответ не публикуется, итоговый становится карточкой знания → эксперт подтверждает → повторный вопрос другими словами отвечается по карточке, без нового письма. |

**Регламент главнее карточки СК.** Карточка дополняет пункты. Если она расходится с действующим пунктом, сотрудник получает однозначный ответ по регламенту, а расхождение попадает в «Реестр изменений регламента».

**Противоречия в регламентах.** Ночной анализатор находит пары пунктов-кандидатов → СК подтверждает на странице «Противоречия» → сотрудник видит оба пункта и правило «пока регламент действует, поступать вопреки нельзя; срочно — индивидуальное согласование с руководителем, у которого есть полномочия», а СК получает письмо с задачей изменить регламент.

## Что получает служба качества

- **Обращения** — вопрос, диалог, статус.
- **Письмо эксперту с черновиком ответа** — экономит время эксперта.
- **Карточки знаний** — однажды разобранный случай больше не отнимает время.
- **Реестр изменений регламента** — ответы СК, подтверждённые противоречия и расхождения разъяснений с регламентом одним списком задач.
- **Мониторинг повторов** — «этот вопрос задавали N раз за период» → сигнал письмом.
- **Аналитика** — что спрашивают, чего нет в регламентах, журнал запросов.
- **Настройки** — темы, которые СК разбирает вне регламентов; период и порог повторов. Действуют сразу, без кода.
- **Документы** — реестр и загрузка регламентов (DOCX; PDF, сканы, фото — через doc-intel); новое подразделение — без правки кода.

## Подход и архитектура

```
вопрос ─► разбор (LLM: термины регламента, дирекции, тип вопроса; расшифровки сокращений из текста документов)
        ─► поиск: BM25 + bge-m3 → RRF → реранкер bge-reranker-v2-m3 (сначала по всей базе, затем вглубь в лучших документах)
        ─► ответ по каждой дирекции параллельно (LLM, JSON-схема, дословные цитаты)
        ─► агентный второй проход для слабых ответов (добор пунктов по ссылкам «п. X.Y», соседних и недостающих)
        ─► проверки кодом: цитата, числа, роли, запрет ↔ разрешение, опора каждой фразы итога
        ─► решение: ответ / уточнение / письмо в СК / «вне регламентов» (+ реестр противоречий, карточки СК)
```

| Модуль | Где |
|---|---|
| Нормализатор документов: нарезка по пунктам / заголовкам / без раздела, окна 600–1000 знаков с путём раздела; DOCX, HTML/Confluence, PDF и сканы | `app/chunking`, `app/parsers`, `app/ingest` |
| Поиск и ответ | `app/search`, `app/answer`, `app/dialog`, `app/pipeline.py` |
| Служба качества: обращения, письма (SMTP; в демо — Mailpit), разбор ответов эксперта, карточки, повторы | `app/escalation` |
| Противоречия: ночной анализатор и реестр | `app/analysis/conflicts.py`, `app/analysis/registry.py` |
| Коннектор Confluence (Cloud v2 и Server/DC, без аддонов, инкрементально по версии страницы; проверен на записанных ответах API) | `app/connectors/confluence.py` |
| Конфигурация вместо кода: подразделения, синонимы, маршруты «вне регламентов», темы СК, мониторинг | `config/documents.json`, `config/synonyms.json`; веб «Настройки» |
| Веб-интерфейс и API | `ui/`, `app/api/server.py` |

Роли в интерфейсе: «Сотрудник» (чат) и «Служба качества» (обращения, знания, реестр изменений, противоречия, аналитика, настройки, документы).

## Стоимость эксплуатации

Оценивается логика: из чего складывается стоимость одного вопроса.

**1. Вопрос = сумма шагов агента.** Модель вызывается несколько раз:

| Шаг | Когда | Вызовов на вопрос | Токены вход / выход |
|---|---|---|---|
| Разбор вопроса | всегда | 1 | ≈ 1 150 / 100 |
| Ответ по дирекции (с цитатами; включая второй проход) | по каждой дирекции, где есть опора | 1,7–2,0 | 6 700–8 200 / 380–520 |
| Сравнение дирекций / проверка темы | перед уточнением, на границе домена | 0,2–0,4 | ≈ 100–180 / 10–20 |
| Черновик для эксперта СК | только при письме в СК | +1 | — |
| Поиск: эмбеддинги + реранкер | всегда | ≈ 12 поисков | — |

**2. Своя модель на своей видеокарте** (так работает стенд): цена токенов — 0, платим за электричество. Замер на RTX 5090: под нагрузкой в среднем 474 Вт, простой 81 Вт → **0,94 Вт·ч на вопрос ≈ 0,0075 ₽** (8 ₽/кВт·ч). Нагрузка заказчика ~120 вопросов в день → ≈ 20 ₽/мес на ответы; простой карты круглые сутки ≈ 470 ₽/мес (ночью её занимает проверка регламентов на противоречия). Остальной сервер не замерялся.

**3. Для сравнения — та же модель у официального провайдера** (Alibaba Model Studio, $0,5 / $3 за 1 млн токенов вход / выход, курс ЦБ 82,313 ₽/$, без НДС): простые вопросы ≈ 0,48 ₽, все классы ≈ 0,53 ₽, трудные многодирекционные ≈ 0,58 ₽ (ответ готовится по каждой дирекции). 120 вопросов в день ≈ 1,4 тыс. ₽ в месяц.

**4. Что не растёт с базой.** Поиск идёт сначала по всей базе, затем вглубь только в лучших документах: на базе в 75 раз больше число поисков и вызовов модели на вопрос то же, значит и цена вопроса.

**5. Разовые и фоновые затраты (не входят в цену вопроса):** распознавание PDF и сканов и векторы окон — один раз при загрузке документа; ночной анализатор противоречий — опция по расписанию, на большой базе — инкрементально, только пары изменённых документов.

**6. Экономия.** Повторный вопрос закрывается карточкой знания без письма в СК: 0 минут эксперта. Мониторинг повторов показывает, где эта экономия.

Заполненный шаблон организаторов — по ссылке в форме сдачи.

## Запуск и поставка

```bash
# демо без моделей (BM25 + заглушка модели) — интерфейс и сценарии
python3 -m app.api.server --corpus <папка с регламентами> --data data/app --mock --port 8080

# стенд: ассистент + Mailpit
cd deploy && docker compose up -d
```

- `deploy/compose.yaml` поднимает ассистента и Mailpit. Сервисы моделей запускаются отдельно и задаются переменными окружения: `LLM_BASE_URL` (OpenAI-совместимый vLLM; на стенде — kv-кэш fp8, контекст 16 384, prefix caching, без рассуждения), `TEI_EMBED_URL`, `TEI_RERANK_URL`, `DOC_INTEL_URL` (только для PDF и сканов). Наружу сервисы не слушают; вход — через обратный прокси с паролем.
- После перезапуска видеокарты эмбеддинги поднимать раньше vLLM: прогрев эмбеддингов требует свободной памяти.
- Подключение компании — конфигурация, не код: подразделения и документы (`config/documents.json`), адрес почты СК (`QA_EMAIL`, SMTP), темы СК и мониторинг повторов (веб «Настройки»).
- Тесты: `python3 -m unittest discover -s tests`.
- Проверка качества: `scripts/eval/answer_eval.py` (прогон набора вопросов), `scripts/eval/funnel.py` (воронка поиск → контекст → цитата → исход и парное сравнение прогонов), `scripts/eval/scenario.py` (сценарий кейсов 1–3).

### Анализатор противоречий

`scripts/stand/conflicts.sh <корпус>` (`app/analysis/conflicts.py`): поиск противоречий, неоднозначностей и различий дирекций между пунктами. Кандидаты по теме и сигналам кода, судья LLM, цитаты проверяются кодом; каждую находку перепроверяют три независимых судьи, итог по большинству с полем «уверенность». Окончательное решение — за СК в реестре.

- Быстрый режим: `<корпус> 300` (бюджет пар, без перепроверки). Без моделей: `--offline`.
- Инкрементально: `<корпус> prev=<metrics.json прошлого прогона>` — только пары с пунктами нового или изменённого документа.
- По расписанию — строкой crontab в часы наименьшей нагрузки; на стенде автоматически ничего не ставится.
- Кандидаты в реестр сервера: `scripts/eval/conflicts.py <корпус> db=<data/app.sqlite>` или `POST /api/conflicts/import`.

## Наработки до хакатона и компоненты третьих лиц

- **doc-intel** — наш компонент разбора документов (файл → текст, блоки, таблицы; распознавание LightOnOCR-2-1B), создан до хакатона. Подключается по HTTP API, его кода в репозитории нет. Нужен только для PDF и сканов; DOCX разбирается кодом этого репозитория.
- До старта подготовлены спецификация, тексты промптов и макеты — Положение это разрешает.
- Модели и программы третьих лиц — в разделе «Стек и модели», все с открытыми лицензиями.
- Весь код помощника написан в этом репозитории с 26.11 10:00 МСК; первый коммит до старта — пустой репозиторий.

## Не реализовано (следующие шаги)

- **Модуль интеграций:** справочники, разделы частых вопросов заказчика, правовые базы по API, MCP.
- **Посредник для внешних вопросов** с обезличиванием: внутреннее наружу не уходит, во внешнюю базу — только обезличенный общий вопрос.
- **«Учтите также»** (дополнительные пункты в ответе) — проверено, не включено: давало ошибки в верных ответах.
- **Многодирекционные ответы без пропуска дирекции** — главный источник ошибок на трудных вопросах.
- **Несколько вопросов в одном сообщении.**
- **Быстрый ответ** — второй проход в фоне.
- **Импорт кандидатов ночного анализатора, отклонённых перепроверкой**, — на подтверждение СК.
